# Opportunity Mining for Profitable Solo SaaS

This is the discovery prompt.

The important rule: **do not generate products first. Find real pain first.**

---

```text
# Deep Research: Opportunity Mining for Profitable Solo SaaS

## Objective

Run a broad, evidence-based opportunity-mining research process.

The explicit goal is NOT to immediately generate SaaS ideas.

Instead, find real situations where companies, self-employed professionals, specialists or prosumers currently:

- repeatedly lose time
- manually work between multiple systems
- use Excel / Google Sheets / CSV as an intermediate solution
- copy and paste data
- manually create reports
- manually validate or clean data
- convert files between systems
- pay freelancers, agencies or virtual assistants
- pay for oversized software although they only need a small part of it
- repeatedly complain about workflows in existing products
- face new problems because of APIs, regulations or platform changes

We are looking for pain signals and workflow friction first, NOT finished product ideas.

---

## Overall goal

I am a solo developer and want to build a portfolio of several small software products.

Long-term portfolio target:

approximately EUR 15,000 MRR

A single product does not need to become a unicorn.

Products that could realistically reach roughly:

EUR 1,000–3,000 MRR

are interesting.

Examples:

- 25 customers × EUR 79
- 40 customers × EUR 49
- 70 customers × EUR 29
- 150 customers × EUR 15

A small market is completely acceptable.

---

## Builder profile

Prefer opportunities that can be implemented by an experienced solo developer.

Technical complexity is generally fine.

Especially suitable:

- Web SaaS
- APIs
- integrations
- automation
- data processing
- monitoring
- reporting
- developer tools
- browser extensions
- Shopify apps
- WordPress plugins
- marketplace apps
- workflow tools
- B2B micro-SaaS
- focused prosumer products

Prefer:

- self-service
- low support load
- low infrastructure costs
- no manual service per customer
- no large enterprise sales process
- no mandatory sales calls
- no hardware
- no marketplace that requires solving a cold-start problem
- no network effect as a prerequisite

---

## Core research rule

DO NOT INVENT PRODUCTS YET.

During the discovery phase, do NOT write:

"One could build an app that..."

Instead, find concrete observations such as:

"Users export a CSV from System A every week, manually modify it and import it into System B."

or:

"Agencies pay employees to compile the same monthly report from five data sources."

or:

"Users pay EUR 150/month for Software X, but according to reviews mainly need Feature Y."

or:

"Since a platform change in 2025, operators must perform Process Z manually."

Only after enough real signals have been collected may you form product hypotheses.

---

## Phase 1 — Find at least 100 real pain signals

Search broadly across markets and industries.

Every signal must come from an observable source.

Suitable sources include:

### Communities

- Reddit
- Hacker News
- Indie Hackers
- industry-specific forums
- public Facebook communities where searchable
- indexed Discord/community discussions where available
- Stack Overflow
- GitHub Discussions

Search especially for statements such as:

- "I have to manually..."
- "Every week I..."
- "We export..."
- "We still use Excel..."
- "I wish X could..."
- "Does anyone know a tool for..."
- "How do you handle..."
- "We built an internal spreadsheet..."
- "I pay someone to..."
- "This takes me hours..."
- "There must be a better way..."
- "I only need this one feature..."
- "Why does this cost so much..."
- "We switched because..."

---

## Phase 2 — Review mining

Search:

- G2
- Capterra
- Trustpilot
- Shopify App Store
- Chrome Web Store
- WordPress Plugin Directory
- Atlassian Marketplace
- HubSpot Marketplace
- Salesforce AppExchange
- GitHub Issues
- public support forums
- Apple App Store
- Google Play

Do NOT primarily search for low ratings.

Recurring concrete workflow problems are more interesting.

Especially valuable:

"Feature X is bad."

"We still have to finish this in Excel afterward."

"The export does not work for our process."

"We only need X but have to buy the whole product."

"The tool works, but then we still need to do Y manually."

"We would like to connect Tool A with Tool B."

"The product is too complex for our small business."

"Since Update X, our old workflow no longer works."

Document recurring patterns.

One angry user is not an opportunity.

Investigate:

- CSV preparation

- listing management

- PDF generation
- compliance documentation
- monitoring
- audit preparation
- data reconciliation

Especially interesting are tasks where the human mostly:

collect information from several sources
→ structure it
→ create a report

Document:

- exactly what is being done
- how often
- roughly what customers pay

## Phase 5 — New market changes

Search intensively for changes from roughly the last:

6–24 months

and only secondarily up to 36 months.

Investigate:

- new APIs
- API deprecations
- new API limits
- new privacy requirements
- EU regulation
- Apple rules
- Google rules
- Shopify changes
- Stripe changes
- Meta changes

- platform migrations

Always ask:

What new manual work did this create?

What existing software now works worse?

What workflow exists today that did not exist two years ago?

These opportunities can be especially interesting because incumbent vendors have had less time to fully cover the market.

## Phase 6 — Marketplace mining

Investigate platforms where users actively search for extensions.

Especially:

- Shopify App Store
- WordPress Plugin Directory
- Chrome Web Store
- Atlassian Marketplace
- HubSpot Marketplace
- Slack Marketplace
- Microsoft Teams Apps
- GitHub Marketplace
- Figma Plugins
- Notion Integrations

Search for:

- categories with strong demand
- apps with many installations but recurring complaints
- workflows where users combine multiple apps
- apps charging surprisingly high prices
- abandoned or poorly maintained products
- products with poor recent reviews despite a large user base

Document not only the product, but the underlying workflow.

---

## Phase 7 — "Ugly spreadsheet" mining

Find situations where users or companies maintain their own:

- Excel sheets
- Google Sheets
- Airtable bases
- Notion templates
- CSV processes
- internal databases

Especially interesting:

- the spreadsheet is used by multiple employees
- the spreadsheet needs regular updates
- data comes from other systems
- errors have financial consequences
- users even sell templates for this workflow
- YouTube tutorials exist such as "How I manage X in Google Sheets"

Do not automatically turn this into a CRUD app.

First investigate why the spreadsheet survives even though software already exists.

## Phase 8 — Cluster the strongest pain signals

After collecting raw signals, cluster similar problems.

Example:

20 separate complaints about:

- Shopify CSV export
- supplier CSV
- SKU mapping
- formatting
- imports

may describe one common workflow.

For every cluster document:

### Problem

What happens concretely?

### Users

Who has the problem?

### Frequency

- daily
- weekly
- monthly
- occasionally

### Existing Spend

What do people pay for today?

### Existing Solution

How is the problem currently handled?

### Why is it unsatisfactory?

What is missing?

### Evidence Count

How many independent signals were found?

### Evidence Quality

Distinguish between:

- one statement
- multiple users
- recurring review complaints
- paid freelancer market
- existing specialist software
- demonstrable business spend

## Phase 9 — Only now form product hypotheses

Select the:

10–20 strongest opportunity clusters

Only now may a potential software solution be formulated.

For each opportunity:

### Product Hypothesis

In no more than two sentences, describe what a small product could do.

### Target User

Be very specific.

Do NOT write:

"Small businesses"

Prefer something like:

"Shopify merchants with 500–10,000 SKUs and supplier CSV feeds."

### Existing Workflow

Which steps are currently performed?

### Existing Spend

What does the current process cost?

### Pain

What is actually painful?

### Frequency

How often does it happen?

### Reason to Buy

Why would someone pay extra for this?

### Replacement Required?

Would the user have to replace existing software?

Prefer:

NO.

### Technical Scope

Can an experienced solo developer build a meaningful first core in a few weeks?

At least one realistic passive or semi-passive acquisition channel should be conceivable.

## Important: do not kill too early

This discovery research should NOT require the same level of evidence as a final BUILD decision.

Distinguish:

### Weak Signal

Interesting, but little evidence.

### Emerging Opportunity

Several real signals, but important questions remain open.

### Strong Opportunity

Recurring pain + existing spend + credible reason to buy.

### Ready for Full Validation

Enough evidence to justify a separate market / SEO / competitor validation.

Only kill candidates that are obviously weak.

---

## Research principles

- Discover problems. Do not hallucinate ideas.
- Weight user behavior more heavily than keyword data.
- Weight existing spend more heavily than theoretical willingness to pay.
- Weight multiple independent signals more heavily than one complaint.
- Prefer companion products over full replacements.
- Pay special attention to new market changes.
- Explicitly allow small markets.
- Competition is not automatically negative.
- Lack of competition is not automatically positive.
- Do not derive an opportunity solely from low SEO difficulty.
- Do not recommend a product based on one Reddit comment.
- Do not manufacture artificial BUILD candidates.
- State uncertainty openly.

The result of this research should NOT immediately decide BUILD / KILL.

Its purpose is to find the best real raw opportunities.

Those should then be evaluated separately for:

- market
- willingness to pay
- competition
- standalone value
- SEO / ASO / marketplace distribution
- pricing
- MRR potential
- BUILD / VALIDATE / KILL
```
